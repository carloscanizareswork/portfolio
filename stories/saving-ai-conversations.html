Maximizing Context, Minimizing Costs

As we build more sophisticated AI agents, we inevitably hit the "Infinity Context" wall. While modern models like GPT-4 and Gemini Pro offer massive context windows, sending the entire history of a long-running conversation in every prompt is both a performance killer and a budget drain.

Today, I want to explore how we can handle long-term agent memory efficiently by combining summarization, vector storage, and automated synchronization.

The Problem: The Token Inflation

Every shared turn in a conversation repeats the previous turns. By the 50th message, you're paying for the 1st through 49th messages over and over again. This logarithmic cost curve quickly becomes unsustainable for enterprise-grade applications with thousands of active users.

The Goal: Maintain a "Sticky Memory" where the agent remembers the core facts of the interaction without the overhead of the "as-is" raw transcript.

Strategy 1: Rolling Summarization

The first line of defense is recursive summarization. Instead of saving the raw text, we generate a structured summary of the key findings, user preferences, and decisions made so far. We run this every 15 messages and store the result in Firebase.

At runtime, we only inject the latest summary plus the last 15 raw messages into the context window. That keeps the prompt tight while still preserving recent nuance.

Key strategies to provide context to the agent:

  • System Messages: Inject conversation summaries and user preferences at the beginning
  • Sliding Window: Keep only the last 15 messages in full detail
  • Metadata Injection: Add structured data about user profile, past decisions, and facts
  • Structured Summaries: Ask the model for a consistent markdown or JSON summary

Strategy 2: Single Vector File (RAG) for Infinite Recall

For truly long dialogues, summarization isn't enough—details get lost. This is where Vector Storage comes in. Instead of managing many embeddings, we keep a single rolling summary document that is always up to date.

The Practical Approach: One Rolling Summary File

Here's the key shift: we keep only one vector file per conversation, not one file per 15 messages. Every 15 messages we regenerate the summary, store it in Firebase, and replace the vector file in OpenAI with the new content. That means the vector store always represents the latest consolidated summary.

// Generate updated structured markdown summary
const summaryMarkdown = await generateSummary(messages);

// Upload to OpenAI as a file
const file = await openai.files.create({
  file: Buffer.from(summaryMarkdown),
  purpose: "assistants"
});

// Replace the previous file in the vector store
await openai.vectorStores.files.delete(vectorStoreId, oldFileId);
await openai.vectorStores.files.create(vectorStoreId, { file_id: file.id });

Simplified RAG Architecture

📝 Step 1: Generate Summary
Every 15 messages → AI creates an updated rolling summary
↓
📤 Step 2: Replace Vector File
Upload the new summary → replace the existing file
↓
💾 Step 3: Re-index Automatically
OpenAI re-chunks, re-embeds, and re-indexes the file
⟲
🔍 Step 4: Automatic Retrieval
User asks question → OpenAI searches vectors → Returns relevant context
↓
🤖 Step 5: Response Generation
Retrieved context + current message → LLM generates informed response

Why this approach wins:

  • ✅ Simplicity: No manual embedding management—OpenAI does it all
  • ✅ Human-readable: Markdown summaries can be reviewed/audited easily
  • ✅ Automatic chunking: OpenAI handles optimal text segmentation
  • ✅ Built-in retrieval: File search tool integrates seamlessly with assistants
  • ✅ Less code: Fewer moving parts = fewer bugs

When to use manual embeddings instead: If you need vendor independence, use a custom vector DB (Pinecone, Supabase), or require fine-grained control over chunking strategies. For most applications, a single rolling summary file is the sweet spot between simplicity and effectiveness.

This approach allows us to maintain "infinite memory" while only using a fixed amount of tokens per request. The AI can recall specific details from conversations that happened weeks ago, without sending thousands of messages in every prompt.

Automating the Workflow

To make this seamless, we automate the process. A background task runs every 15 messages to:

  • Retrieve the latest summary from Firebase
  • Fetch the last 15 messages and append to the summary prompt
  • Generate the new consolidated summary and store it back in Firebase
  • Replace the single vector file in OpenAI with the updated summary

AI-Powered Summarization Pipeline

The summarization process itself is powered by AI. We use a dedicated prompt template that instructs the model to:

// Automated Summarization with AI
const summaryPrompt = `
Create a structured markdown summary of this conversation segment:

## Conversation Context
- User: ${userId}
- Date Range: ${startDate} to ${endDate}
- Messages: ${messageCount}

## Requirements
- Extract key facts, decisions, and user preferences
- Identify important dates, names, and commitments
- Highlight unresolved questions or pending actions
- Maintain chronological order of critical events
- Use clear markdown formatting (headers, lists, bold for emphasis)

## Conversation Segment
${recentMessages.join('\n---\n')}

${previousSummary ? `## Previous Summary\n${previousSummary}` : ''}
`;

const summary = await openai.chat.completions.create({
  model: "gpt-4-turbo",
  messages: [{ role: "user", content: summaryPrompt }],
  temperature: 0.2
});

// Returns markdown like:
// # Conversation Summary
// ## Key Preferences
// - Prefers modern design
// - Budget: $50k-75k
// ## Decisions Made
// - Venue: Riverside Manor (confirmed 2026-01-10)

This automated approach ensures consistency and reduces manual overhead. The AI identifies patterns and extracts actionable insights that would be tedious to capture manually. Plus, markdown format makes summaries debuggable and auditable.

Cost Comparison

OpenAI Vector Store Pricing (2026):
  • Storage: $0.10/GB/day
  • Embedding: Included (automatic)
  • File Search: Free with Assistant API

Typical costs: A markdown summary file is 2-5KB. For 100 users with 10 summary files each = ~5MB = ~$0.0005/day. Negligible compared to token costs savings!

Conclusion: Efficiency is the New Scale

By moving away from "Send All" to "Retrieve Relevant," we reduce costs by up to 80% while increasing the agent's perceived intelligence. The future of AI interaction isn't about larger windows—it's about smarter memory management.

🎉 Real-World Application: Smart Weddings AI Agent

We successfully implemented this exact architecture in our Smart Weddings project, where an AI wedding planning agent helps couples organize their big day. The agent needs to remember preferences discussed weeks ago (venue style, budget constraints, guest list details) while having natural conversations.

Results achieved:

  • Reduced token costs by 75% for long-running conversations (50+ messages)
  • Agent accurately recalls venue preferences from 2 weeks prior
  • Maintains context across multiple planning sessions over months
  • Summarization pipeline runs nightly via Cloud Functions
  • Vector search enables instant recall of specific vendor discussions

The wedding planning domain is perfect for this approach because conversations are inherently long-term, detail-rich, and require perfect recall of user preferences across multiple sessions. Our clients love that the AI "remembers" everything without them having to repeat themselves.
